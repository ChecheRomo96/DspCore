From the equation to one output sample
There is no stateless for an IIR filter: depends on the current input plus previous and values. processSample computes the first summation from numerator_ and inputHistory_, subtracts the feedback summation from denominator_ and outputHistory_, then shifts both histories. Reset establishes zero initial conditions. This is direct form I, expressed with separate input and output delay lines.

Coefficients can come from any valid discrete-time design method. For example, Biquad returns a normalized second-order numerator and denominator that Configure can consume directly; a bilinear transform or a measured model can supply higher-order coefficients in the same convention.

The stream's SampleType is intentionally independent from both coefficient storage and recurrence StateType. StateType defaults to CoefficientType. Arithmetic for the recurrence occurs in StateType, followed by conversion to SampleType at the output boundary. Process accepts direct, caller-owned Processing::SampleBlock input and output views; it does not participate in a graph or own a stream transport.

Applies the IIR recurrence to equally sized caller-owned sample blocks.

The method allocates neither stream memory nor temporary buffers. Both views must be valid and have exactly the same size. It validates the complete input before changing filter state or output. A later arithmetic conversion failure may leave a valid processed prefix and its corresponding updated delay state.

Exact in-place processing is supported when both blocks begin at the same address. Different, partially overlapping ranges are unsupported.
