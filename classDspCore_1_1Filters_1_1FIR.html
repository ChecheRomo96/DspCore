The caller supplies as Coefficients::taps, usually from a filter design method such as a windowed-sinc, least-squares, or measured impulse response. This class implements that recurrence; it does not choose the taps or infer a filter shape.
From the equation to one output sample
Process does not evaluate a memoryless . Each current input produces the next output using the current sample and the stored input history. Internally, processSample starts with , walks the circular delay line to add , then writes into that line for the next call. The delay line is zero after construction or Reset, which gives the usual zero initial conditions.

SampleType is the stream representation. CoefficientType controls the tap representation, while StateType controls the multiply-accumulate and delay line precision. The accumulated is converted to SampleType only at the processor boundary. Process accepts direct, caller-owned Processing::SampleBlock input and output views; it does not participate in a graph or own a stream transport.

Applies the FIR recurrence to equally sized caller-owned sample blocks.

The method allocates neither stream memory nor temporary buffers. Both views must be valid and have exactly the same size. It validates the complete input before changing filter state or output. A later arithmetic conversion failure may leave a valid processed prefix and its corresponding updated delay state.

Exact in-place processing is supported when both blocks begin at the same address. Different, partially overlapping ranges are unsupported.
