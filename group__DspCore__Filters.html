Detailed Description

Two generic SISO ProcessorBase implementations, configured by coefficients.

Include <DspCore_Filters.h> or FIR.h/IIR.h. Coefficient calculators are functions in Biquad coefficient calculators, not processing classes. Process advances one complete input block with processor-owned persistent history. Both filters also implement DspCore::Processing::ProcessorBase with one input and one output port: block processing advances the same state once per input value and produces the same number of output values. No processing, Process and Reset do not allocate, schedule, clip or throw. Configure may resize processor-owned CPSTL storage.

Processing contracts

  • SPEC-FILT-1: Float/double samples, coefficients and computed state must be finite. Invalid configuration/update leaves coefficients, history and output unchanged. A successful Configure resets delays. Scalar input and output may alias. Raw coefficient array extent is a caller precondition.
  • SPEC-FILT-2: FIR<T> owns numerator coefficients and input history in cpstd::vector storage. Configure accepts any positive finite runtime tap count, reallocates only there, resets history and makes that count observable through Taps(). b[0] multiplies the current input. Default configuration is one-tap identity. Equation: y[n]=sum(b[k]*x[n-k]).
  • SPEC-FILT-3: IIR<T> owns numerator, denominator and their delay histories in cpstd::vector storage. Configure accepts independently sized, positive runtime counts through raw pointers/counts, array references, or a struct exposing numerator and denominator arrays. All values must be finite and a0 nonzero. Normalize every coefficient by a0 and validate the result before committing. Negative a0 is supported. Source arrays/structs are unchanged.
  • SPEC-FILT-4: IIR uses the generic direct-form I recurrence: y[n]=sum(b[k]/a0*x[n-k])-sum(a[k]/a0*y[n-k], k>=1). Default configuration is identity. History and normalized coefficients are processor-owned; copying a filter duplicates state. Configure resets history, may resize storage and may cause transients. No automatic coefficient smoothing is performed.
  • SPEC-FILT-5: The ProcessorBase block overload requires exactly one valid finite input and one output with capacity for the complete input block. Invalid views and non-finite input are rejected before processing. On a finite arithmetic failure, OutputBlock::size reports the valid prefix already committed. Successful blocks have one output per input and no added windowing latency.

Generic IIR validates representability, not arbitrary-order pole stability. Callers supplying custom coefficients own their stability decisions. Biquad calculators check strict second-order stability before returning a design. A finite configuration does not guarantee finite results for every input; overflow rejects that sample without consuming it or clipping it.

auto coefficients = DspCore::Filters::Biquad::LowPass(48000.f,1000.f,0.707f);
DspCore::Filters::IIR<float> filter;
if (!filter.Configure(coefficients)) { return; }
const float input[]={1.f,0.f};
float output[2]={};
bool ok=filter.Process(input,output,2);
