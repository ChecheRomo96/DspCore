Detailed Description

Runnable, reproducible walkthroughs of the public DspCore API.

An example is a small program intended to be read, changed and run. It demonstrates a workflow and gives a human-readable result; it is therefore different from a test. Tests assert contracts automatically and may exercise edge cases that are deliberately not part of a first explanation. Examples are closer to a MATLAB live script: source, command, output and the meaning of that output live together.

Each tutorial below contains its goal, the specific API behavior it makes visible, a desktop command, representative output captured from the current build, and the portable Shared.cpp implementation used by both the desktop adapter and Arduino sketch. Filter tutorials also contain their generated figure and native CSV-producing adapter.

Run an example

./scripts/build.sh macos_arm64 --examples-on
./build/macos_arm64/bin/Debug/DspCore_Core_Version_d

The source layout intentionally keeps the tutorial logic portable:

examples/<module>/<example>/
|-- CMakeLists.txt # native target definition
|-- <example>.ino # Arduino entry point
|-- Shared.h # portable entry point
|-- Shared.cpp # code shown by the tutorial
`-- Desktop/main.cpp # desktop adapter, when required

Desktop output and plotting tools

examples/Tools/ contains optional host-side helpers for the filter tutorials. These scripts are not part of DspCore, are not compiled into an Arduino sketch, and are not needed by an embedded consumer.

File Purpose
plot_signal.py Reads a signal CSV and produces a PNG with NumPy and Matplotlib.
plot_signal.m MATLAB equivalent of the Python plotter.
render_signal.sh macOS/Linux wrapper for the Python plotter.
render_signal.ps1 Windows PowerShell wrapper for the Python plotter.

examples/Tools/ has no CMakeLists.txt because these are scripts rather than build targets. The examples build copies them beside its executables; exported Release examples ship them beside the launcher. Doxygen uses only the versioned PNG snapshots in Images/, so reading the documentation never requires Python or MATLAB.

The filter adapters write CSV files to ~/Documents/DspCoreExampleOutput/ by default. Select another directory with --output and render a result:

./build/macos_arm64/bin/Debug/DspCore_Filters_FIR_d --output ./output
./build/macos_arm64/bin/Debug/render_signal.sh ./output/fir_moving_average.csv
plot_signal("output/fir_moving_average.csv")
