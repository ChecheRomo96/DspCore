Detailed Description

Float/double interpolation arithmetic and explicit LUT boundaries.

Include <DspCore_Interpolation.h> or <DspCore/Interpolation/Arithmetic.h> for standalone formulas. LUT lookup additionally requires the LUT module and <DspCore/Interpolation/Lookup.h>. No operation allocates, throws or modifies table storage.

Arithmetic

Linear(a,b,t) evaluates a line with normalized t; Bilinear and Trilinear compose it on independent normalized axes. Values outside [0,1] extrapolate. No boundary policy is hidden in the formulas. Use consistent float or double arguments (or an explicit template argument); integer-only arithmetic is rejected at compile time. Double computations are never reduced to float.

Corner order is x-fast, matching LUT storage:

  • Bilinear: f00, f10, f01, f11, x, y.
  • Trilinear: f000, f100, f010, f110, f001, f101, f011, f111, x, y, z.

f(x,y) = L(L(f00,f10,x), L(f01,f11,x), y)

Linear returns exact endpoints at t=0 and t=1 and uses a weighted form for opposite-sign endpoints to avoid overflowing their difference during interpolation. NaN/Inf samples may propagate; extrapolation may overflow. Results are not clipped. Exact endpoints select the corresponding sample even if an unused sample is non-finite.

Physical coordinates

TryUnitCoordinate(x,low,high,t) validates finite coordinates and ascending bounds. TryLinear/TryBilinear/TryTrilinear normalize physical coordinates before applying the formulas. Each span, subtraction and normalized result must be representable. Reversed or collapsed bounds fail rather than divide by zero. Failure leaves the output unchanged. Extrapolation is permitted. The bool reports coordinate validity, not finiteness of sample arithmetic.

double value = 0;
// Physical x=15 in [10,20], output endpoints 2 and 8: value=5.
bool ok = DspCore::Interpolation::TryLinear(10.,20.,2.,8.,15.,value);

Normalized LUT lookup

Lookup(table, coordinates..., output, policy) returns bool and takes an explicit Boundary policy shared across axes:

Boundary Domain and indexing
Clamp Clamp to [0,1]; position=x*(N-1), with exact first/last endpoints
Reject Same closed indexing, but outside [0,1] returns false
Wrap Wrap cycles into [0,1); position=x*N, interpolating last-to-first

Wrap tables contain N distinct periodic samples without a duplicate endpoint. Thus a four-sample table has sample 1 at phase 0.25. Closed tables include both endpoints; their sample 1 is at coordinate 1/3. Negative phase and arbitrarily many finite cycles wrap with fmod.

Empty tables, invalid policies and non-finite coordinates fail without changing output. Singleton axes are constant for valid coordinates and still obey Reject; no division by zero occurs. Interior indexing requires the extent to fit the exact-integer range of the calculation type and be smaller than size_t's maximum, avoiding unsafe floating-to-index casts.

The floating output/coordinate type selects arithmetic independently of table storage. Integer samples convert to that type without PCM scaling. Narrowing sample overflow explicitly produces signed infinity; NaN remains NaN. Lookup success reports valid indexing, not finite sample values. Select double coordinates and output to preserve double sample precision.

DspCore::LUT::LUT1D<float> table;
if (!table.Resize(2)) { return; }
table.SetValue(0, 0.0f); table.SetValue(1, 10.0f);
float value = 0;
bool ok = DspCore::Interpolation::Lookup(
table, 0.25f, value, DspCore::Interpolation::Boundary::Clamp);
// value=2.5; no allocation during lookup.
